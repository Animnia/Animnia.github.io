01

The problem

AI gateways, resellers, and proxies sometimes serve a different — cheaper — model than the one they advertise.

Benchmarks are gameable. Dashboards are curated. The model field in an API response is just a string that anyone can write. When the invoice says one model and the weights belong to another, every soft signal can be forged.

Glitch tokens cannot. A glitch token lives in one vendor's tokenizer but barely appeared in its training data — so that vendor's models mangle it on a verbatim-copy task, while everyone else copies it perfectly. The failure is a property of the weights, not of the metadata.

02

The method

1

Probe

Send a strict copy instruction holding a vendor-specific glitch token. No explanation, translation, or correction allowed.

2

Judge

Compare the reply against the token, whitespace-insensitive and Unicode-normalized. Reproduced is a success; anything else is a failure.

3

Confirm

The same token must fail twice in two fresh probes. Request errors are retried once and never counted as evidence.

A live probe 请原样复制 <target> 标签内的全部文本。 不得解释、翻译、纠错、补充或省略。 <target>开通天眼生意通银牌及以上会员</target>
The verdict Qwen-family models garble this string; others reproduce it exactly. Two failures. One candidate. Evidence, not vibes.

04

What a match tells you — and what it never will

A match means

  • The observed behavior matches a known vendor family.
  • Strong circumstantial evidence, recorded per token, twice confirmed.
  • A finding worth acting on — and worth stating plainly.

A match never means

  • A specific model version is verified.
  • Proof that a provider is dishonest.
  • That an "unknown" result clears anyone — the fingerprint set is small and experimental.
05

Install it where your agent lives

terminal
pi install npm:glitch-lens
# or
pi install git:github.com/Animnia/glitch-lens
Four tools — glitch_lens_scan, glitch_lens_self_scan, glitch_lens_delegated_start, glitch_lens_delegated_advance — plus a skill that teaches pi when and how to use them. Self-scan reuses pi's resolved provider auth; keys are never printed.
terminal
codex plugin marketplace add Animnia/glitch-lens
codex plugin add glitch-lens@animnia
A Codex plugin with the glitch-lens skill, invoked with $glitch-lens. Runtime model and provider are read from the session transcript; probes execute in fresh codex exec sessions to minimize context contamination.
terminal
claude plugin marketplace add Animnia/glitch-lens
claude plugin install glitch-lens@animnia
A Claude Code plugin with the glitch-lens skill, invoked with /glitch-lens. The runtime model is read from the session transcript via claude-runtime; transcripts carry no provider field, so none is claimed.
terminal
hermes skills tap add Animnia/glitch-lens
hermes skills install Animnia/glitch-lens/glitch-lens
A Hermes skill that passes the hub security scan. Audit the endpoint Hermes is configured against, or run a delegated self-scan with probes in fresh hermes chat sessions.
terminal
# Node.js ≥ 20, no install needed
npx -y glitch-lens scan --protocol openai \
  --endpoint https://api.example.com/v1 \
  --model some-model --key-env EXAMPLE_API_KEY --json
The same engine as a plain CLI. Keys are only ever read from the environment variable you name — never accepted inline, never printed.
06

Reading a result

match

Exactly one vendor candidate confirmed — two fresh copy failures on the same token. Report the vendor family.

conflict

Several vendor families confirmed at once. Report them all; never pick a favorite.

unknown

No fingerprint confirmed. Inconclusive — not an exoneration. The fingerprint set is small.
